## 2. Classification Definitions

1. **`TAUGHT` (applies-and-agrees):** The task is governed by a Handbook v2 house convention that is *not* discoverable from the ticket, docstring, or repository code alone. The hidden test follows deterministically from the rule text.
2. **`DISTRACTOR` (applies-and-conflicts):** The handbook rule appears relevant to the domain, but the local module docstring explicitly mandates an override ("MUST ... instead", "do NOT use ..."). Tests cognitive interference and resistance to over-compliance.
3. **`STATED` (applies-and-agrees):** The governing rule is explicitly documented within the local ticket or docstring. The baseline agent can solve it without access to the handbook.
4. **`TRANSFER` (applies-and-agrees):** Tasks belonging to novel, 100% held-out bug families (Family 7 `cache_ttl`, Family 14 `state_transitions`) testing cross-domain heuristic generalization.

## 5. Methodological Invariants (J1–J5 & Automated Sufficiency J2)

1. **Condition J1 (Local Grounding):** Every task is grounded in an actual defect in `benchmarks/suite_e5.py`.
2. **Condition J2 (Rule Sufficiency & Determinism):** Verified by `runner/verify_rule_sufficiency.py` and `test_rule_sufficiency_j2` in `tests/test_suite_e5_preflight.py`. All asserted constants, error codes, service prefixes, header names, and formats are derivable from `HANDBOOK.md` + repo context.
3. **Condition J3 (Coverage Balance):** All active house rules are exercised by multiple distinct tasks across independent families.
4. **Condition J4 (Distractor Specificity):** Distractor tasks have explicit, unambiguous override clauses in local docstrings.
5. **Condition J5 (Transfer Independence):** Transfer families are 100% held-out and test conceptual generalization rather than direct memorization.
