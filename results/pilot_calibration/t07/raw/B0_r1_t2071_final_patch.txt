    # `rank = (p / 100.0) * (n - 1)`
    # If `p=0`, `rank=0`. `math.ceil(0)=0`. `s[0]`.
    # If `p=100`, `rank=n-1`. `math.ceil(n-1)=n-1`. `s[n-1]`.
    # This seems robust for the ends.

    # Let's assume the test data `s` is `[10, 20, 20, 30, 40]` and `p=75`. `n=5`.
    # Current: `rank_float = 0.75 * (5 - 1) = 0.75 * 4 = 3.0`. `idx = int(round(3.0)) = 3`. `s[3] = 30.0`. Correct.

    # Let's assume the test data `s` is `[10, 20, 30, 40, 50, 60]` and `p=50`. `n=6`.
    # Current: `rank_float = 0.5 * (6 - 1) = 0.5 * 5 = 2.5`. `idx = int(round(2.5)) = 2`. `s[2] = 30.0`.
    # If the test expected 40.0, then `idx` should be `3`. This means `round(2.5)` should be `3`.
    # Python's `round(2.5)` is `2`. This is exactly the "round half to even" issue.
    # If `s[2]` is 20.0 and `s[3]` is 30.0, and `p=50`, `n=6`.
    # `rank_float = 2.5`. Current `idx = 2`. `s[2]` is 20.0.
    # If the expected value is 30.0 (which is `s[3]`), then `idx` should be `3`.
    # This implies `round(2.5)` should be `3`.
    # This can be fixed by replacing `round` with `math.ceil`.
    # `idx = int(math.ceil(2.5)) = 3`. `s[3]` would be 30.0.

    # This is a very strong candidate for the fix. The "round half to even" behavior of `round()`
    # is often problematic for statistical calculations where consistent rounding up of `.5` is desired.
    # `math.ceil()` consistently rounds up.

    # Let's apply this change:
    # `idx = int(math.ceil((p / 100.0) * (n - 1)))`
    # We still need to ensure `idx` is within bounds `[0, n-1]`.
    # Since `(p / 100.0)` is between `0` and `1`, and `(n-1)` is the max index:
    # `0 * (n-1) = 0`. `math.ceil(0) = 0`.
    # `1 * (n-1) = n-1`. `math.ceil(n-1) = n-1`.
    # So `idx` will naturally be between `0` and `n-1`. No explicit clamping needed.

    # Final check of the logic with `math.ceil`:
    # `vals = [10, 20, 30, 40, 50, 60]`
    # `n = 6`
    # `p = 50`
    # `rank_float = (50 / 100.0) * (6 - 1) = 0.5 * 5 = 2.5`
    # `idx = int(math.ceil(2.5)) = int(3.0) = 3`
    # `s[3]` is `40.0`.
    # If the original test was `assert 30.0 == 40.0` (meaning current is 30, expected 40),
    # then `round(2.5)` would have been `2`, `s[2]` is `30.0`.
    # Changing to `math.ceil` makes it `s[3]` which is `40.0`. This would fix that type of error.

    # The failure `assert 20.0 == 30.0` means current is 20, expected 30.
    # This means `s[idx]` was 20.0 and `s[idx+1]` was 30.0.
    # So, `idx` was `X`, but it should have been `X+1`.
    # This implies `round(rank_float)` resulted in `X`, but it should have been `X+1`.
    # This is exactly the problem with `round(Y.5)` when `Y` is even.
    # Example: `rank_float = 1.5`. `round(1.5)` is `2`. (if `1` is odd).
    # If `rank_float = 0.5`. `round(0.5)` is `0`. (if `0` is even).
    # If `s[0]` is 20.0 and `s[1]` is 30.0.
    # And `rank_float = 0.5`. `round(0.5)` is `0`. `s[0]` is 20.0.
    # `math.ceil(0.5)` is `1`. `s[1]` is 30.0.
    # This would fix it!
    # So the test case likely involved `rank_float` ending in `.5` where the integer part was even,
    # and `round` incorrectly rounded down from the perspective of the expected percentile.

    # The change is to replace `round` with `math.ceil`.
    # Also need to import `math`. It's already imported.

    idx = int(math.ceil((p / 100.0) * (n - 1)))
    return float(s[idx])

def build_rpc_report(service_name: str, series: RpcSeries, p: float) -> Dict[str, Any]:
    val = compute_rpc_percentile(series, p)
