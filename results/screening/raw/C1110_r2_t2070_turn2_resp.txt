The `max(0, min(idx, n - 1))` clamping is technically redundant because `idx_float` is already in `[0, n-1]` for `p` in `[0, 100]`. If `p=0`, `idx_float=0`, `idx=0`. If `p=100`, `idx_float=n-1`, `idx=n-1`. Any `p` between 0 and 100 will result in `idx_float` between 0 and `n-1`, so `floor(idx_float)` will be between 0 and `n-1`. I can simplify this.

Refined `calculate_percentile` logic:

"""Percentile estimation engine for database telemetry."""
import math
from typing import List

def calculate_percentile(values: List[float], p: float) -> float:
    """Calculates percentile across sample values.

    This method determines a rank index `k = (p / 100.0) * (n - 1)`,
    where `n` is the number of values. The percentile value is then
    returned from the sorted list at index `floor(k)`.
    If `p` is 0, the minimum value is returned. If `p` is 100, the maximum value is returned.
    This approach effectively floors the rank index, meaning if the percentile falls
    between two values, the lower value is returned. This helps to make SLA
    calculations more conservative by not interpolating upwards past an existing data point.
    """
    if not values:
        raise ValueError("Empty values")
    s = sorted(values)
    n = len(s)
    
    # Calculate the float rank index. For 0-indexed array, this value ranges from 0 to n-1.
    idx_float = (p / 100.0) * (n - 1)
    
    # Take the floor of the index. This ensures that if the true percentile falls
    # between s[i] and s[i+1], it defaults to s[i].
    idx = int(math.floor(idx_float))
    
    # The index idx_float is guaranteed to be within [0, n-1] for p in [0, 100].
    # Therefore, floor(idx_float) will also be within [0, n-1].
    # No explicit clamping is needed as long as p is valid.
    
    return float(s[idx])
