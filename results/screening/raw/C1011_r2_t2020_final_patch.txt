The core issue is that `is_topic_subscribed` uses `startswith`, which is too broad for matching root topics. A subscription to "orders" should only match event topics that *are exactly* "orders" or begin with "orders::". It should not match "orders_admin" or "orders_internal".

To fix this, when the `subscribed_topic` does not contain a "::", it implies a subscription to a root topic. In this case, it should match the `event.topic_root()` exactly, or match event topics that begin with the subscribed root followed by "::".

Let's refine `should_dispatch_webhook`:

If `subscribed_topic` is "orders":
- `event.topic_path = "orders::created"` should match. `event.topic_root() = "orders"`.
- `event.topic_path = "orders_admin::created"` should NOT match. `event.topic_root() = "orders_admin"`.

The simplest way to achieve this is to ensure that if the `subscribed_topic` itself is a root (e.g., "orders"), we compare it directly with the event's `topic_root()`. If the `subscribed_topic` is more specific (e.g., "orders::created"), then the existing `startswith` logic on the full `topic_path` is appropriate.

Revised approach for `should_dispatch_webhook`:
If `subscribed_topic` itself contains "::", then it's a specific sub-topic subscription, and `is_topic_subscribed(subscribed_topic, event.topic_path)` is correct.
If `subscribed_topic` does *not* contain "::", it's a root topic subscription. In this case, we must ensure `subscribed_topic` matches `event.topic_root()` exactly.

```python
from prefix_validator import is_topic_subscribed
from webhook import WebhookEvent

def should_dispatch_webhook(subscribed_topic: str, event: WebhookEvent) -> bool:
    """Determine if webhook event topic is permitted under the subscription filter.

    A subscription to 'orders' should match 'orders::created' but not 'orders_admin::created'.
    """
    if "::" not in subscribed_topic:
        # If subscribed_topic is a root (e.g., "orders"), it should only match events
        # whose root topic is exactly that, or events that start with "orders::"
        # The is_topic_subscribed function uses startswith, so if we pass
        # "orders" and "orders::created", it will match.
        # But if we pass "orders" and "orders_admin::created", it would also match.
        # The key is to check if the subscribed_topic is an exact match for the event's root,
        # OR if the event's full topic path starts with the subscribed_topic followed by '::'.
        # A simpler way is to ensure the event's topic_root is exactly the subscribed_topic.
        return subscribed_topic == event.topic_root()
    else:
        # If subscribed_topic includes '::' (e.g., "orders::created"),
        # then the standard startswith logic applies to the full path.
        return is_topic_subscribed(subscribed_topic, event.topic_path)

```

"""Webhook scope dispatch checker."""
from prefix_validator import is_topic_subscribed
from webhook import WebhookEvent

def should_dispatch_webhook(subscribed_topic: str, event: WebhookEvent) -> bool:
    """Determine if webhook event topic is permitted under the subscription filter.

    A subscription to a root topic (e.g., 'orders') should only match events
    whose root topic is an exact match (e.g., 'orders::created' matches,
    but 'orders_admin::created' does not).
    For more specific subscriptions (e.g., 'orders::created'), the event's
    full topic path must start with the subscribed pattern.
    """
    if "::" not in subscribed_topic:
        # If the subscribed_topic is a root (e.g., "orders"),
        # it must exactly match the event's root topic.
        return subscribed_topic == event.topic_root()
    else:
        # If the subscribed_topic is specific (e.g., "orders::created"),
        # use the standard 'startswith' logic on the full topic path.
        return is_topic_subscribed(subscribed_topic, event.topic_path)

def filter_dispatch_queue(subscribed_topic: str, events: list) -> list:
    return [e for e in events if should_dispatch_webhook(subscribed_topic, e)]

def batch_topic_summary(events: list) -> dict:
    summary = {}
    for e in events:
        summary[e.topic_path] = summary.get(e.topic_path, 0) + 1
    return summary
